# MiniLims 云服务器部署指南（git 中转 + 服务器构建版）

> 部署方式：**本地 push 代码到 git 远程仓库 → 云控制台网页终端（账号密码登录）在服务器上 git clone/pull → 服务器 Docker 构建运行**。
> 适用场景：服务器 **SSH 已被移除**（此前因开放端口遭入侵），管理通道只剩云控制台网页终端（VNC/OrcaTerm）。
> 本版与仓库根目录 `docker-compose.yml`、`MiniLims.Vue3/Dockerfile + nginx.conf` 严格对应。

---

## 0. 部署架构总览

```
┌───────────── 本地（Windows） ─────────────┐      ┌──────────── 云服务器 118.89.200.74 ────────────┐
│ VS Code / 命令行                           │      │ 云控制台网页终端（VNC/OrcaTerm，账号密码登录） │
│   1. 改代码                                │      │   1. git clone / git pull （代码经 git 中转）  │
│   2. git commit + git push   ──── git ────►│      │   2. cp .env.example .env（填密码）           │
└──────────────────────────────────────────┘      │   3. docker compose up -d --build（服务器构建）│
                                                  │   4. minilims-api(:8888) + minilims-web(:80)    │
                                                  │       │  ──host.docker.internal──► existing mysql8 / redis │
                                                  └───────────────────────────────────────────────┘
```

- **无 SSH、无 scp/sftp**：所有文件传输都走 git 仓库中转；`.env`（含密码）**不进 git**，在服务器上手动创建。
- **复用已有 `mysql8`、`redis` 容器**（`mini_lims` 库数据完好），本项目只部署 api + web；api 容器经
  `extra_hosts: host-gateway` 以 `host.docker.internal` 访问宿主机 3306/6379，**不依赖公网端口回环**。
- 构建在服务器执行：后端 restore NuGet、前端 yarn（Dockerfile 已配 npmmirror 源）。

## 3. 服务器：拉代码 + 改复用版配置 + 填密码

### 3.1 服务器端配置 SSH 通道并拉代码

> ⚠️ 实测：服务器直连 `https://github.com` 返回 `Empty reply from server`（被墙），
> 与本地一致。因此服务器必须使用 **SSH-over-443 通道**（GitHub 官方通道，绕过封锁），配置步骤与本地完全相同。

**步骤 1：生成 SSH 密钥（在服务器终端执行）**

```bash
ssh-keygen -t ed25519 -C "minilims-server" -f ~/.ssh/id_ed25519_github -N ""
cat ~/.ssh/id_ed25519_github.pub
```

**步骤 2：把输出的公钥添加到 GitHub**

GitHub → Settings → SSH and GPG keys → New SSH key（可加多把 key，与本地那把并存）。

**步骤 3：配置 SSH-over-443（服务器终端）**

```bash
cat >> ~/.ssh/config <<'EOF'
Host github.com
    HostName ssh.github.com
    Port 443
    User git
    IdentityFile ~/.ssh/id_ed25519_github
    IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config

# 验证：应输出 "Hi runingsee! You've successfully authenticated..."
ssh -T git@github.com
```

**步骤 4：克隆代码**

```bash
cd ~
git clone git@github.com:runingsee/MiniLims.git
# 若之前已 clone：cd MiniLims && git pull
```

> ⚠️ 云服务器默认用户是 `ubuntu`（非 root），**不要用 `/opt`**（无写权限，报 `Permission denied`）。
> 克隆到用户主目录 `~/MiniLims` 即可，后续 `sudo` 仅 docker 操作需要。

### 3.2 使用"复用版" docker-compose.yml

⚠️ 仓库自带的 compose 是自包含版，**部署到已有库的服务器必须先替换**。两种方式任选：

**方式一（推荐，本地改好再 push）**：本地把 `docker-compose.yml` 改成下面内容 → `git commit + push` → 服务器 `git pull`。
**方式二（服务器直接改）**：在服务器上 `vi docker-compose.yml`，把 `services` 与 `volumes` 整体替换为下面内容。

复用版完整配置：

```yaml
services:
  # mysql / redis 已注释：复用宿主机已有 mysql8、redis 容器
  api:
    build:
      context: ./AMiniLims
      dockerfile: MiniLims.Admin.WebApi/Dockerfile
    container_name: minilims-api
    restart: unless-stopped
    extra_hosts:
      - "host.docker.internal:host-gateway"   # 关键：让容器访问宿主机 3306/6379
    environment:
      TZ: Asia/Shanghai
      dbConfigs__0__Conn: "Server=host.docker.internal;Port=3306;Database=mini_lims;Uid=root;Pwd=${MINILIMS_DB_PWD};CharSet=utf8mb4;SslMode=None;"
      dbConfigs__0__ConfigId: "0"
      dbConfigs__0__DbType: "0"
      dbConfigs__1__Conn: "Server=host.docker.internal;Port=3306;Database=mini_lims;Uid=root;Pwd=${MINILIMS_DB_PWD};CharSet=utf8mb4;SslMode=None;"
      dbConfigs__1__ConfigId: "1"
      dbConfigs__1__DbType: "0"
      CodeGenDbConfig__Conn: "Server=host.docker.internal;Port=3306;Database={dbName};Uid=root;Pwd=${MINILIMS_DB_PWD};CharSet=utf8mb4;SslMode=None;"
      RedisServer__Cache: "host.docker.internal:6379,password=${MINILIMS_REDIS_PWD},defaultDatabase=0,poolsize=50,ssl=false,writeBuffer=10240,prefix=cache:"
      RedisServer__Session: "host.docker.internal:6379,password=${MINILIMS_REDIS_PWD},defaultDatabase=0,poolsize=50,ssl=false,writeBuffer=10240,prefix=session:"
      Upload__uploadUrl: "/prod-api"
    ports:
      - "8888:8888"
    volumes:
      - dataprotection_data:/app/DataProtection
      - uploads_data:/app/wwwroot/uploads
  web:
    build:
      context: ./MiniLims.Vue3
      dockerfile: Dockerfile
    container_name: minilims-web
    restart: unless-stopped
    ports:
      - "80:80"
    depends_on:
      - api

volumes:
  dataprotection_data:
  uploads_data:
```

### 3.3 创建 .env（含密码，不进 git）

```bash
cd ~/MiniLims
cp .env.example .env
vi .env          # 填入与宿主机 mysql8 / redis 完全一致的密码
chmod 600 .env
```

`.env` 内容（两行）：

```bash
MINILIMS_DB_PWD=你的MySQL-root密码
MINILIMS_REDIS_PWD=你的Redis密码
```

> 如果嫌 vi 删行麻烦：`vi .env` 后按 `ggdG` 清空，再 `:set paste` 粘贴两行，`Esc` → `:wq`。

### 3.4 （可选）Docker 镜像加速

服务器在国内拉 `mcr.microsoft.com / docker hub` 基础镜像可能慢，可配腾讯云/阿里云镜像加速器
（控制台 → 容器镜像服务 → 镜像加速器，把加速地址写进 `/etc/docker/daemon.json` 后重启 Docker）。

## 4. 构建并启动（服务器终端）

```bash
cd ~/MiniLims
docker compose up -d --build
```

首次构建 5~10 分钟（拉基础镜像 + NuGet + yarn），耐心等待；中途可另开一个终端用 `docker compose ps` 观察。

验证：

```bash
# 服务器本机
curl -i http://127.0.0.1:8888/        # 后端 200
curl -i http://127.0.0.1/ | head -20  # 前端静态页
docker compose ps                       # minilims-api / minilims-web 均为 Up
```

浏览器访问（需本地可访问 80/8888，见 §6 安全组）：<http://118.89.200.74/> → 登录 `admin / <密码见 .env 或部署者口令>`。
验证项：能登录、样本/报告页可打开、上传图片可回显、实时消息可用。

> 云端 `mini_lims` 库已有表，**不需要**执行 `--initdb`。只有确认目标库为空才需：
> `docker compose build api && docker compose run --rm api --initdb`。

## 6. 安全加固（本次被入侵后必做）

> 服务器曾被入侵，多半与 3306/6379 等端口对外开放有关。部署完成后建议按序收紧：

### 6.1 云安全组端口收敛（控制台操作）

| 端口 | 服务 | 建议 |
|---|---|---|
| 80 | 前端 nginx | 保留开放（0.0.0.0/0）|
| 8888 | 后端 api | 生产不需对外（Swagger 已关）。建议仅允许你本地办公 IP，或直接关闭，前端经 nginx `/prod-api` 反代访问 |
| 3306 | MySQL | **关闭对外或仅允许你的办公 IP 白名单**。容器内已走 `host.docker.internal` 访问宿主，不需要公网回环 |
| 6379 | Redis | 同上，**关闭对外或白名单**。Redis 强密码（`--requirepass`）必须已设置 |
| 22 | SSH | 已移除，保持关闭 |

> 本地开发仍连 `118.89.200.74:3306/6379` 的话，安全组把来源限制为**你的固定公网 IP**（控制台支持来源 IP 白名单），而不是 0.0.0.0/0。

### 6.2 MySQL/Redis 账号检查（服务器终端）

```bash
# MySQL：确认无多余远程账号，root 密码强度足够
docker exec mysql8 mysql -uroot -p -e "SELECT user,host FROM mysql.user;"

# Redis：确认 requirepass 已启用
docker exec redis redis-cli -a "你的密码" CONFIG GET requirepass
```

### 6.3 其他

- 服务器系统用户建议禁用 root 直接登录/设强密码（有 VNC 兜底）。
- 容器自动重启：compose 里 `restart: unless-stopped` 已配置，服务器重启后服务自动拉起。
- 关注 `docker compose logs api` 是否有异常登录/攻击尝试。

## 7. 日常运维（全部在云控制台终端）

| 操作 | 命令 |
|---|---|
| 看状态 | `docker compose ps` |
| 看后端日志 | `docker compose logs -f api` |
| 看前端日志 | `docker compose logs --tail=200 web` |
| 备份数据库 | `docker exec mysql8 mysqldump -uroot -p"$MINILIMS_DB_PWD" --databases mini_lims > ~/backup/mini_lims_$(date +%F).sql` |
| 停服务 | `docker compose stop` |
| 重启服务 | `docker compose start` |
| 彻底停（保留卷） | `docker compose down` |
| 清理旧镜像 | `docker image prune` |

> 上传文件在 `uploads_data` 卷、登录密钥在 `dataprotection_data` 卷（服务器磁盘，`down` 不删卷）。
> 数据卷目录（腾讯云默认 `/var/lib/docker/volumes/`）建议通过云控制台做**磁盘快照**定期备份。

## 8. FAQ

| 现象 | 原因与处理 |
|---|---|
| `git clone` 提示认证失败 | GitHub 用 PAT（Settings → Developer settings → Personal access tokens）当密码；Gitee 可直接账号密码。确认仓库是 **私有** 且给了该账号权限 |
| `docker compose up` 报 mysql/redis 服务找不到 | 用的是仓库**自包含版** compose，没替换成 §3.2 的复用版（或没有 `extra_hosts: host-gateway`） |
| api 反复重启、日志报连不上 MySQL/Redis | ① `.env` 密码与宿主机 mysql8/redis 实际密码不一致；② 连接串还写着公网 IP 而非 `host.docker.internal`；③ Docker 引擎过旧（需 20.10+） |
| 首次构建很慢 / restore 卡住 | 基础镜像/依赖拉取慢。配置镜像加速（§3.4）；重跑一次有缓存 |
| 页面能打开但接口 400/404 | nginx `/prod-api/` 的 `proxy_pass http://api:8888/` **尾部斜杠不能丢**；或后端容器没起来（看 api 日志） |
| 上传图片回显 404 | `Upload__uploadUrl` 必须是 `/prod-api`；`uploads_data` 卷挂载正常 |
| 登录后 Token 频繁失效 | `dataprotection_data` 卷被删/重建导致密钥变更。卷在则 Token 持续有效 |
| Swagger 打不开 | 正常：仅 `ASPNETCORE_ENVIRONMENT=Development` 启用，容器内为 Production |
| 实时消息不推送 | 检查 nginx `location /msghub` 的 Upgrade/Connection 头；浏览器 Console 看 `/msghub/negotiate` 是否 101 |
| 想重新初始化空库 | `docker compose build api && docker compose run --rm api --initdb`（会重建表+种子，已有数据会冲突/清空，谨慎） |
